# Demo 交互验收

这份清单按用户操作验收，不用状态内核测试数或覆盖率推导产品可用性。

## 2026-09-12 复现

在 `f55abe4` 上，真实鼠标拖选、双击单元格、Enter 编辑和 F2 编辑四个浏览器用例全部失败。此前测试通过的范围是 Shift 点击/方向键扩选，以及点击独立的 Edit value 按钮后进行编辑；这些用例没有证明直接操作表格的入口完整。

同时发现，直接打开原来的底部编辑器会把长表滚到末尾。即使文本框存在并获得焦点，这个用户流程仍然退化。

## 本次验收入口

`tests/browser/demo-direct-interaction.spec.ts` 从真实 demo 开始，用鼠标和键盘触发，不通过 Workspace API 或内部测试 fixture 创建选区/编辑会话。

- 鼠标按下、拖动、释放后得到准确的矩形成员；批量编辑只改变这些成员，保存并重新打开后保持，撤销恢复原值。
- 双击实际目标单元格；编辑器获得焦点和该单元格原值。
- 无效输入、第二次编辑手势、页面刷新不能覆盖原编辑会话；恢复后保存只修改原目标。
- Enter 和 F2 对焦点单元格发起编辑。
- 长表编辑区与表格共享可视空间，打开编辑不会滚到表尾；拖选触及滚动区边缘能选到末行，释放后移动鼠标不会继续改选区。

功能回归仍需覆盖矩阵粘贴、填充、排序/过滤、图片、跨表操作和恢复路径，新增入口通过不能代替这些验证。

## 尚不能宣称与旧版交互完整等价

旧版支持的 Ctrl/Cmd 追加不连续选区、普通字符直接开始编辑、历史操作键盘快捷键，以及完整的行/列表头选择与大表交互，需要逐项恢复和验收。当前矩形选区不等于不连续多区域选择。未完成这些验收前，不应再将“当前测试通过”报告为“整个系统功能正常”或“重构交互全部完成”。
