# Demo 交互对照验收

基线：重构前 `2106634`（0.3.1）。目标是恢复原产品交互，保留 Workspace 作为唯一数据与输入所有者。API breaking change 不代表允许删除用户功能。尚未完成整份对照清单，不能据测试总数宣布重构完成。

## 当前执行方式

按用户要求，集中实现剩余旧版能力后再统一浏览器验收和修正。实现期间仅做必要编译检查；
不逐交互新增测试、不反复运行全量。统一验收发现问题后只跑相关用例，发布前再做完整检查。
现有测试先保留，数量和覆盖率不作为完成标准。

本批已写入、尚未完成浏览器验收：Quick start 250ms 自动保存、自动/手动保存进度、
问题标记及统计、批量编辑中英文文案、同列右键批量编辑复用、图片类型/大小统一预检、
编辑提交期间的双击切换和选区拖动。不能将这些实现记录当作验证通过。

范围核对：旧版没有通用图片 BulkEditor，也没有虚拟滚动；二者不列为新开发前置项。
跨表的独立历史与当前共享 Workspace 历史仍有行为差异，必须单列解决，不能靠改文案算对齐。

## 验收方法

以实际 demo 的鼠标、键盘和浏览器剪贴板作为入口，核对原值、目标成员、编辑、校验、提交、源保存及重开。内核 fixture 用于注入存储确认丢失、来源更新、权限变化等失败，不代替产品入口验收。

`tests/browser/interaction-parity.spec.ts` 对照旧版检查：

- Ctrl/Cmd 追加不连续选区，批量写入准确并集，不能写入选区之间的空洞。
- 行号、列表头、左上角选择，表头拖选，鼠标和键盘调整列宽。
- 单元格内编辑、原值选中、字符直接输入、Enter 校验/提交、Tab 提交后移动、Escape 明确取消。
- 普通单元格编辑时点击另一格、行头、列头或全选：先完整校验、确认并应用输入，再切换选区；无效输入保留原选区与焦点。存储确认丢失期间不能提前移动。明确的 Review grid 支持保留输入并检查其他目标。
- 连续输入与立即提交；编辑开放的持久化确认不能丢掉后续字符。旧编辑完成后的焦点恢复不能抢走新编辑或用户已经选择的控件。
- 布尔值直接勾选、单选项点击即应用、多选项勾选后应用或取消，选项身份与顺序保持。
- 表头过滤对话框和批量编辑对话框；关闭后的焦点恢复。
- 文本批量前后缀、查找替换、正则替换。所有参数属于 Workspace 输入，刷新后可恢复；无效正则不能产生部分写入。
- 真正 Ctrl+C / Ctrl+V 从活动单元格扩展矩阵，整块校验、应用、保存、重开。无效矩阵保留原文，不能部分修改数据。

`tests/browser/demo-direct-interaction.spec.ts` 继续覆盖长表编辑、滚动区边缘拖选、释放后的终止、无效输入及重开。`workspace-grid.spec.ts`、`workspace-copy.spec.ts` 等继续核验固定身份、隐藏/删除目标、别名字段、再次粘贴的拒绝输入、恢复与保存证据。

## 本轮定位的链路问题

1. 将成熟的单元格编辑 UI 替换成独立输入框，原有交互没有进入验收标准。
2. 编辑会话等待持久化确认时，没有接收后续键入的入口。`Workspace.beginEditing` 现在在同一 ingress 队列中保留开放请求和后继输入；拒绝开放时也保留完整请求链。
3. 组合输入已结束但已发布状态仍显示 composing，导致立即按 Enter 被忽略。提交意图现在等待最新输入确认，并绑定会话身份。
4. 临时与已确认编辑器换 DOM 节点，导致输入选区丢失；编辑器现在保持相同控件结构。
5. 编辑器定位只监听尺寸，未监听提示/复核内容引起的位置变化；几何变化不得改变逻辑编辑目标。
6. 异步提交后恢复焦点，会覆盖用户已选择的新控件；焦点恢复必须核对发起控件和当前编辑状态。
7. 只监听普通单元格的 paste 事件不能覆盖所有浏览器原生快捷键。需要瞬时可编辑接收节点，并处理 WebKit 原生剪贴板 `types` 为空但可读取文本的情况。
8. 旧版普通编辑通过 prepareTransition 先提交再改变选择；新 UI 绕过这一边界后形成“选中了新格、旧编辑仍占着会话”的状态。现在选择动作等待同一 session-apply 的接受结果，并核对 Workspace/view 所有者后才移动。
9. 行头固定 44px 只适合行号，不能容纳跨表 demo 的选择、拖动和保护标记。rowHeader.width 显式声明宿主控件所需空间，控件保持同行；浏览器检查受保护行的实际行高和文字高度。
10. 模态输入不能阻断恢复入口。明确的 Review grid 保留会话并开放表格/恢复控制；Resume editing 返回输入对话框，不能隐式丢弃或重新确定目标。

## 本轮过滤恢复

标准 codecs 现在提供文本、数字、日期、布尔、单选、多选及图片有无的条件编辑器，支持增删条件、all/any、清除单列。自定义 filters 仍覆盖对应列。条件原文属于 Workspace ingress/session，应用只改变版本化查询，不写数据 journal。

文本匹配显式记录 locale，选择值按真实编码类型匹配。格式 11 引入这些查询语义；格式 12 增加视图归属，格式 13 保存搜索定义，格式 14 增加决策撤销贡献，格式 15 保存字段级决策范围，当前格式 16 保存会话中的新行目标，仍读取格式 10–15 并在后续提交中升级。无法表示的宿主查询保留原表达式，允许明确清除，不近似转换为另一种过滤含义。

浏览器故障测试发现 Firefox 对同一次编辑发出两个内容和 composition 均相同的结束事件，恢复后尾部重复请求阻塞了继续编辑。浏览器输入入口现在只合并与 Workspace 最新输入完全相同的事件，保留不同内容、组合状态、被拒绝输入和失效身份的处理。内核命令本身仍保留每次明确请求。

`tests/browser/filter-parity.spec.ts` 验证多条件大小写匹配、类型范围、标签与日期、清除单列保留其他列、丢失确认后的条件恢复，以及无法表达的查询在明确清除前继续生效。

Playwright 改为使用自己的全新 4179 端口服务器，避免复用已 HMR 的开发服务产生两份 fixture 模块；4178 继续用于开发预览。不能把此环境故障当作产品流程通过。

### 冲突菜单与决策撤销

已接入整行 Use remote row / Keep local row，传递菜单打开时的 revision、
observation、完整 issueIds 和 intentIds；状态变化关闭旧菜单，不按新状态
自动重写用户决策。单格解决还不能映射成整行解决：批量输入可能把多个字段
放在同一贡献记录中，直接丢弃该记录会误清除其他字段。

`conflict-menu-parity.spec.ts` 曾暴露 Undo 只恢复输入、不恢复冲突的模型差异。
现在追加带新身份及原始比较/依赖的恢复贡献；Undo 恢复本地值和冲突，Redo
先处置恢复贡献再准备数据重放。原始回执和丢弃证据保持不可变。

若恢复贡献已被一次提交占用，Redo 必须等待该提交的确定结果，不能提前
把它标记为丢弃。回归先复现了错误的提前重做，再验证等待期间状态与输入
保持不变、成功回执后恢复重做。三浏览器覆盖确认丢失、刷新重开、确认后
重做，并核对来源只写入一次。模型另外覆盖远端删除后的重新创建、创建
冲突后采用已有行，在保存前后撤销/重做及反复操作时恢复冲突和完整行数据。
单格菜单现已接入字段级决策：同一写入组中未处理字段保留原比较与依赖，
撤销/重做和重开后仍保留其他冲突。三浏览器验证处理一格后另一字段继续
阻止保存，明确处理剩余冲突后才写入来源。整行比较、跨越字段边界的父级
写入仍要求完整范围审查，不隐式缩小比较域。复杂语义读取等组合仍需继续核验。

### 重构验收的责任与修正

此次故障的直接证据包括 demo 中缺少多选和双击编辑，以及决策撤销的原
设计只恢复输入、不恢复用户看到的值与冲突。它们说明重构把内核契约当成了
完整产品契约，遗漏了旧版用户操作的保留要求。允许 API breaking change
不能作为移除已有交互的依据。

测试数量和分支覆盖率不能证明旧版工作流仍能完成；按新实现预期编写的测试
也可能固化错误行为。此次决策撤销的原测试就是具体例子：它要求显示远端值，
而旧版浏览器实际撤销后显示本地值并恢复冲突。

后续验收以基线产品操作及来源最终记录为依据，覆盖正常操作、失败时输入
保留、确认丢失和刷新重开。内核测试验证数据不变量，浏览器验证用户入口，
打包消费验证交付产物。三者各自提供证据，任何一层通过都不能替代未完成的
交互对照。未完成清单清零并完成最终回归之前，不发布此次恢复工作。

### 卸载期间的存储写集合

## 排队开放编辑的上下文边界

对图片拖入未启动的时序做了可控验证：拦住 save-schedule-configured 的真实 IndexedDB
成功回调，在保存设置尚未发布时拖入文件，再释放回调。修复前 Chromium、Firefox、WebKit

Workspace.dispatch 现在仅在请求 revision 与当前状态一致时捕获一次 session opening context，
随请求进入持久化队列。上下文包含目标及显式 reads 的逻辑值、权限、编辑器代次和过滤基线。
reduceSession 对带上下文的请求比较这些实际依赖；没有上下文的旧请求仍执行 revision 校验。
真正过期的调用不自动更新 reads，其他 session 的占用仍拒绝。配置及资源登记等无关写入
可以先完成，不再凭全局 revision 把同一目标的用户操作变成错误恢复流程。

浏览器用例验证图片拖入、保存、刷新读取，以及过滤器开放、应用和刷新后查询保留。
旧 durable-ingress 测试原以排队新输入被拒绝来证明“归档旧请求不吞掉后来的输入”；
现改为确认新会话及其完整输入已持久化，且旧请求的 returned 收据保持，重开无需额外 refresh。

最终检查：1264 个单元测试、594 个全量浏览器用例、类型检查、lint、打包消费均通过。
