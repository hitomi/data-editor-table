# 草稿、权威数据与异步操作的状态约束

本文是已删除的旧 draft/controller 实现的历史记录，不是当前 API 或接入指南。下文的“现在”“当前”均指重构前的实现；其中自动按 key 归类、重建历史及卸载取消等规则不能用于新 Workspace。当前协议见 [状态内核重构设计](state-kernel-redesign.md)，接入见 [Workspace 迁移指南](workspace-migration.md)，验收状态见 [验收索引](state-kernel-acceptance.md)。

## 为什么重新整理

之前 `insertedRowKeys` 同时表示“服务器尚无此行”和“已有行的整行替换”。删除入口按前一种含义
取消新增，保存回放按后一种含义保留整行，权限检查又把它当作工厂提供的新行默认值。这导致同一状态
在不同消费者中得到不同解释。单独增加条件无法保证后续命令与历史也正确。

现在用独立的 `replacedRowKeys` 表达整行替换。`row-intents.ts` 的 `deriveGridRowIntents` 根据同一份
权威基线归类所有结构意图，供普通行事务、原子批量事务、远端 rebase 和保存后的相对草稿重建共用。
命令不再手动推断哪些行属于新增。`hasGridDraftChanges` 是保存、刷新和组件切换判断草稿未保存状态的共同入口。

## 不变量

| 状态 | 约束 | 持久化含义 |
| --- | --- | --- |
| `insertedRowKeys` | key 不在 baselineRows 中，但在本地 rows 中 | 新增完整行 |
| `replacedRowKeys` | key 同时在基线与本地 rows 中；有明确整行替换意图且内容不同 | 更新已有行的完整内容 |
| `deletedRowKeys` | key 必须在权威基线中；不能同时是替换 | 删除权威行 |
| `dirtyCells` | 表示字段级输入，不能代替整行替换意图 | 提供字段变化与原值 |
| `conflicts` | 独立于上述意图，阻止对应行进入 proposal | 需要处理分歧后再提交 |

发生删除冲突时，为了展示远端变化，待删除行可以暂时出现在 draft.rows 中；deletedRowKeys 仍保留
删除意图。历史条目的 before/after 都包含 replacedRowKeys，并且每次刷新、保存确认后均对两侧重建，
不能只修正当前可见草稿。

## 转换规则

- 本地新增遇到远端同 key：完整内容不同则转成“替换 + 主键冲突”；相同才视为收敛。
- “保留本地行”：检查当前权威行的权限和只读字段；通过后清除冲突，保留独立的替换意图。
- 删除已有行的替换：生成真正的删除。删除没有权威记录的新行：取消新增，不发送删除请求。
- 远端刷新内容未变化：保留已解决的替换，不制造新冲突。内容变化：产生整行替换冲突。
- 远端删除待替换行：保留本地输入，转为“新增 + 远端删除冲突”；远端重新出现则重新归类。
- 字段编辑使整行恢复到权威值：清除替换意图，避免永远脏或重复发送无变化更新。
- 接受远端/恢复整行：清除该行的替换及冲突；undo 可以恢复原来的输入与意图。

## 保存与回放

保存计划重新检查当前权威数据，既检查普通字段编辑，也检查整行替换。没有 setter 的列要求
本地原始值与权威原始值一致；有 setter 的列仍必须满足当前 `isEditable`。工厂授权只适用于真正新增，
不能用于覆盖已有行的只读字段。冲突处理和最终 proposal 使用同一权限检查。

保存完成后先确认原 proposal，再相对于它重建尚未提交的字段及整行意图。部分保存不得清除受阻行。
整行替换通过独立标记保留隐藏字段；正常新增后的追加编辑按字段重放到服务器主键和规范化后的行。
保存期间追加的删除在确认前一次写入后继续保留。未知结果重试保持原 operation ID 和 proposal，
不能因最新权限或草稿变化而改写可能已经执行的请求。

`changes.updated[].after` 是完整更新内容。接入方若持久化整行替换，不能只读取展示列的 `cells`。
服务器仍负责原子版本与权限检查、幂等执行，以及写后读取的一致性；客户端状态机不能替代这些保证。

## 异步操作与数据源所有权

`GridControllerSnapshot.pendingEffects` 投影控制器当前持有的单元格及外部异步操作数量。启动、完成、
失败、取消都更新它；数量和本次数据/反馈变化作为同一个 Runtime 输入原子发布。

OwnedDataGrid 切换数据源时同时检查草稿、会话和 pendingEffects。上传完成后若产生草稿，仍需保存或
放弃草稿才能切换。显式取消释放待处理操作，过期的 Promise 结果不能写入新数据源。销毁控制器仍会
取消其拥有的操作。订阅者现在能观察到异步操作启动，不能假定启动阶段没有 snapshot 通知。

编辑会话持有异步操作时，提交入口拒绝提前提交，包括点击表格外部引发的隐式提交。显式取消编辑
由控制器同步取消会话拥有的操作并清除会话，不依赖 React 编辑器卸载才能释放 pendingEffects。

## 验证与扩展约束

`row-intent-lifecycle.test.ts` 检查每次发布及所有历史两侧的上述不变量，并覆盖删除双入口、隐藏字段、
只读字段、保存期间追加删除、相同/变化/消失/重新出现的权威行，以及固定种子的交错命令序列。
`save-policy.test.ts` 继续覆盖部分保存、主键映射、三种保存模式和权限恢复。
浏览器测试验证真实编辑、冲突恢复、保存、重新打开、图片拖入和取消后的数据源切换。

添加新的结构操作时必须经过统一的意图归类；添加新的草稿字段时必须同步历史、rebase、保存回放、
保存计划和界面消费者。自行构造 GridDraftState/GridHistoryEntry 的接入应初始化新的替换字段为空数组；
通过 createGridController 获取快照的接入会自动得到完整状态。
