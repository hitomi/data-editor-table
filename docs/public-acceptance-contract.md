# 操作目标、保存确认与可执行动作

### 1. 用户授权时固定目标

同步命令在调用时确定目标。行控件绑定当时的实体，编辑器、批量编辑器、菜单和筛选回调绑定各自打开时的会话。重新打开同一控件也会建立新会话。排序允许实体移动，精确创建回执允许同一实体改键，同键替换产生新实体。异步宿主任务在发起时声明可写单元格及依赖单元格，只能向原目标交付值。执行和人工复核时都须核对目标与依赖，任一失效就拒绝整组并保留可复核材料。

列的 `validate(value)` 只处理当前值。`validateWithRow(value, row)` 声明整行依赖。两者同时配置时，先执行纯值校验，再把通过后的值交给行校验。直接命令、编辑器、批量、粘贴和事务产生同样的依赖，刷新重放和保存准备均须核对它们。

### 2. 保存只确认那一笔冻结写入

物理源、scope 和 epoch 共同标识证据的作用域。精确回执必须匹配冻结请求的操作 ID、摘要和全部提交项，回执版本须覆盖请求基线。该表接纳覆盖提交版本的完整快照并结算对应贡献后，保存才返回 `confirmed`；冻结时有排除项则返回 `partial`。冻结后的编辑仍是待保存工作。快照和回执的身份、文档主键、版本都经过验证才进入共享历史。缺少因果前驱时等待原操作，修正证据可以重送。回执推进读取要求时，现有和新订阅表都能获得同一要求。

每个已发出的查询在本进程跟踪到结束，即使原表已关闭、原保存已返回或另一笔保存已经开始。相互矛盾的有效证据使整个作用域封写，草稿和证据保留。结算前发现矛盾，原保存不得确认；结算后才发现，已返回结果仍归属原操作，争议从发现时起阻止后续写入。宿主核对服务端操作账本后，凭当前争议 ID 和确定性证据显式解除。若核验推翻了已接纳的终局事实，宿主须使用新的权威 epoch 重新核对依赖该事实的工作。重开表、刷新或解决其他争议均不能越过剩余争议。进程重启结束本版的本地追踪。

### 3. 所有保存入口从 Controller 取动作

`selectGridActions(controller.getSnapshot(), target?)` 给出目标有效性、保存、重新保存及原操作恢复的 `enabled`、`target`、`issue`。工具栏、页脚、自定义视图与宿主展示该判断，执行时 Controller 重新核对；自动保存还须匹配当前调度代次。持有旧回调时传回原目标。禁止新保存时先拒绝，再次调用不会隐式提交正在编辑的原文。恢复只作用于指定操作与步骤。离开前另取 `getCloseState()` 核对所有待处理工作。

### 八个验收反例

| # | 操作与顺序 | 可观察结果 |
| --- | --- | --- |
| 1 | 在 A 启动任务后选中 B，或替换一项已声明的读写目标再交付多格结果 | 选区不改变任务目标；过期任务整组拒绝，保留结果。任务无法交付删除选区等命令。 |
| 2 | 回执声明键 a，文档解码为 wrong；与正确快照交换顺序 | 坏回执不占用版本。修正后原操作确认，只提交一次。 |
| 3 | 同一操作的在途查询分别返回精确成功和确定未执行，交换顺序，或在下一笔操作已开始后才返回 | 各表观察到原操作的争议并封写；重复证明幂等。宿主按争议逐项裁定。 |
| 4 | A 得到 v2 回执，A 的补读失败，B 已打开，C 后打开 | B 可用自己的健康连接追到 v2；C 收到同一版本要求或已覆盖它的快照。 |
| 5 | A 发现争议时 B 正在编辑，B 手动或自动保存 | B 不开始新写入，原文保留；各表暂停重新保存，显式解除后重新计算动作。 |
| 6 | 原保存结果未知时再打开编辑器，比较内置、自定义工具栏与宿主 | 三者均禁止新保存，恢复入口只给原操作当前合法的步骤。 |
| 7 | 关闭筛选后打开另一列或重新打开同一列，再触发旧回调 | 旧的改值、应用和取消均不影响新会话。 |
| 8 | 本地改 name，另一端只改 count，在刷新或保存准备时相遇 | 纯值校验可合并；声明行校验则出现依赖冲突并保留输入。 |
